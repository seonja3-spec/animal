# 동물의 종 — 출시 가이드 점검

기준: 사용자가 2026-10-19 제공한 앱인토스 게임 출시 체크리스트와 현재 저장소.
공식 최신 정책 전체를 재조회한 결과나 검수 승인 기록이 아니다.
Windows 로컬·Firebase 배포·콘솔 설정은 이 체크아웃과 다를 수 있다.

## 결론 및 우선순위

현재는 기능 테스트 단계이며 출시 준비 완료가 아니다. P0 항목부터 해결한다.

| 우선순위 | 미완료 사항 | 필요한 다음 작업 |
|---|---|---|
| P0 | 토스 닫기/메뉴가 코인을 가림 | 이번 변경에서 native 상단 별도 48px 여유 + SDK SafeArea 반영. 실제 토스 iOS/Android에서 재확인 |
| P0 | 사용자 식별키 없음 | 공식 게임 식별키 API(User.getAnonymousKey/getAnonymousKey 등)의 최신 계약 확인, 동의/오류 처리와 사용자별 저장 설계 |
| P0 | 서버 지갑·기록 없음 | 사용자 키 기반 코인/전적 서버 저장, 서버 시간 기반 일일 보상과 중복 지급 방지, 기기 변경 복원 검증 |
| P0 | 시스템 뒤로가기/종료 처리 없음 | SDK 시스템 이벤트와 closeView를 사용해 연습·설정 닫기 → 이전 화면 → 홈에서 종료 확인 흐름 구현. 우측 닫기 버튼의 플랫폼 처리도 별도 검증 |
| P0 | 플랫폼 실기기 검증 없음 | 네이티브 닫기, Safe Area/Dynamic Island, 무음/진동/복귀 음악, 화면 방향, 최초 진입 10초 기준 |
| P1 | 광고 미구현 | 아래 광고 설계 확정, 콘솔 광고 그룹 생성 및 공식 보상형 SDK 연동/실광고 QA |
| P1 | 고객 문의 경로 없음 | 실제 운영 문의 주소/채널 확정 후 설정 화면에 제공 |
| P1 | 출시 메타데이터 미확인 | 콘솔 게임 분류, 아이콘·스크린샷·연령·정책·권리 정보를 확인 |
| P2 | 저장소 안내 일부 오래됨 | 이 문서를 현재 출시 점검 기준으로 사용. 이전 설치/업로드 실패 기록은 현재 상태 판단에 사용하지 않음 |

## 1. 접속 및 사운드

| 기준 | 상태 | 근거/남은 검증 |
|---|---|---|
| 10초 이내 첫 화면 | 미검증 | 로컬 빌드는 성공. 실제 토스 신규 설치/콜드 캐시/느린 네트워크에서 측정 필요 |
| 음악·효과음 | 구현, 실기기 필요 | 첫 화면/대전 합성 음악과 카드·종·결과 효과음. 첫 사용자 조작 이후 AudioContext 활성화 |
| 개별 On/Off | 구현 | 설정에서 배경음악·효과음·선택 진동. 같은 기기 설정 저장 |
| 무음/시스템 진동 설정 | 실기기 필요 | 현재 진동은 navigator.vibrate이며 네이티브 햅틱 API 미연동. OS별 지원/무음 동작 확인 필요 |
| 백그라운드 소리 종료 | 브라우저 확인 | visibilitychange/pagehide에서 context suspend와 음악 타이머 중단. 토스 가시성 이벤트 동작 검증 필요 |
| 복귀 시 사운드 | 부분 구현 | 홈은 복귀 후 재생 재시도. 대전은 안전하게 일시정지 상태를 유지하고 계속하기 후 재생. 가이드가 요구하는 복귀 동작과 실기기에서 대조 |

## 3. 사용자 식별·데이터 유지

- 게임 사용자 키를 발급·저장하는 코드가 없다. Firebase 프로젝트 생성/Hosting 배포는 사용자 식별이나 DB 연동을 의미하지 않는다.
- 지갑은 `animal-wallet-v1`, 전적은 `animal-progress-v1` localStorage에만 저장된다.
- 동일 브라우저 재접속은 유지되지만 브라우저 삭제/다른 기기/다른 웹뷰에서 복원되지 않는다.
- 일일 보상은 기기 시각과 클라이언트 저장값이 기준이다. 사용자가 수정 가능하므로 실제 보상·광고 보상의 신뢰 근거로 쓰면 안 된다.
- 서버에서 사용자 키, 날짜(한국 기준), 광고 지급 ID/완료 이벤트 등을 검증하고 거래를 원자적으로 저장해야 한다. 키를 받았다는 사실만으로 서버 요청 인증이 완료되지는 않는다.
- 민감 로그인·결제 정보 수집을 시작한다면 암호화, 접근 권한 및 개인정보 처리 요건을 별도 구현한다. 현재는 로그인/결제 DB 자체가 없다.

## 4. 광고 배치 제안 — 아직 확정/구현 아님

첫 도입은 사용자가 선택하는 보상형 광고 한 종류로 제한한다.

1. 홈의 보상 영역: 무료 일일 코인을 우선 제공하고, 그 아래 또는 별도 보상 창에 `광고 보고 30코인 받기` 버튼을 둔다. 30코인은 제안값이다.
2. 난이도 선택에서 코인 부족: 자동 광고 대신 `무료 코인 확인`과 `광고로 충전` 선택을 제공한다. 코인을 받아도 다시 사용자가 난이도를 선택해야 참가비를 차감한다.
3. 대전 중 카드/종 버튼 주변, 첫 진입, 카드 획득 순간에는 광고를 넣지 않는다. 결과 화면 자동 전면 광고도 첫 버전에서는 넣지 않는다.
4. 별도의 프리로드 상태를 관리하고, 준비 완료 전에는 재생 버튼 대신 `광고 준비 중`으로 표시한다. 준비 실패 시 명시적 재시도 또는 다음 화면 진입에서 제한적으로 재시도한다. 무한 재시도/매 프레임 SDK 호출 금지.
5. 사용자가 광고 버튼을 누르면 대전 타이머와 오디오를 일시정지하고 중복 클릭을 막는다.
6. 공식 SDK의 보상 획득 이벤트만 근거로 지급한다. 단순 닫기·취소·실패에는 지급하지 않고, 같은 광고 이벤트는 서버에서 한 번만 처리한다. 광고 종류에 따라 보상/닫기 이벤트 순서가 다르므로 최신 계약을 따른다.
7. 광고 종료 후 원래 화면으로 돌아오고 사용자 소리 설정을 유지한다. 동작 재개/실패/보상 결과를 알린다.
8. 일일 광고 보상 한도/빈도 제한은 정책과 수익성을 확인한 뒤 확정한다. 지금은 임의의 제한이나 테스트 지급 기능을 출시 코드에 추가하지 않는다.
9. 배너는 첫 출시 범위에서 제외하는 것을 제안한다. 추가한다면 상단/하단 전용 영역을 확보하고 네이티브 내비/카드/종과 겹치지 않게 화면을 다시 맞춘다.

필요 정보: 콘솔 광고 그룹 ID, 공식 SDK 사용 계약과 테스트/실광고 전환 기준,
서버 보상 저장 대상, 지급 코인·한도·취소/실패 안내 문구.
공식 문서와 실제 광고를 검증하기 전까지 광고 기능은 미완료다.

## 5. 보안·안정성

- 앱 소스에 eval/new Function, iframe/외부 웹뷰, 외부 사이트 리다이렉트는 없다. 브라우저 자동 검사에 사용한 임시 도구 코드는 배포 소스가 아니다.
- Vite 정적 CSR 빌드이며 SSR 서버가 없다. 실제 .ait 번들을 토스에 업로드해야 토스 도메인에서 렌더링된다.
- Firebase Hosting은 외부 브라우저 테스트용 별도 배포다. 토스 안에서 Firebase URL을 iframe/웹뷰로 불러오는 방식으로 전환하지 않는다.
- 현재 외부 게임 API/웹소켓/결제 API 통신은 없다. 추후 API는 HTTPS, 실시간 연결은 WSS만 허용한다.
- 음악 타이머, 대전 예약 타이머, 화면 효과는 화면 전환/일시정지에 맞춰 정리한다. 실제 장시간 메모리/전력 프로파일링은 아직 하지 않았다.
- Safe Area는 단일 구독으로 변경 시에만 갱신한다. 사용자 키/광고 등을 프레임 반복문에서 호출하지 않는다.

## 6. 서비스 동작·기능별 적용 범위

| 기준 | 상태 | 다음 확인 |
|---|---|---|
| 안드로이드 시스템 뒤로가기 | 미구현 | 플랫폼 이벤트 연동 및 실제 종료 흐름 |
| 게임 풀스크린 | 브라우저 구현 | 100dvh, 스크롤 없는 게임 화면. 토스 네이티브 내비와의 공존 확인 |
| 화면 방향 | 미확정 | 현재 세로 화면으로 설계. 콘솔/SDK의 세로 모드 설정 및 회전 시 동작 확인 |
| UI·2초 내 응답·주요 게임 흐름 | 자동 검사 확인 | 규칙/지갑/기록 테스트와 브라우저 대전. 저사양 기기 터치/렌더링/장시간 QA 추가 |
| 권한 동의/거절 | 현재 대상 기능 없음 | contacts/location/camera 등의 권한을 요청하지 않음. 추가할 때 기능별 최소 권한과 거절 동작 구현 |
| 비정상 네트워크/메모리 증가 | 미측정 | 모바일 장시간·느린 네트워크 프로파일링 필요 |
| 종료 확인 모달 | 미구현 | 현재 `대전 포기` 확인만 있으며 미니앱 종료 확인이 아님 |
| 불법/선정 콘텐츠 | 코드상 특별 요소 없음 | 코인 참가비·보상과 게임 분류는 콘솔/정책 확인 필요. 검수 통과 보장 아님 |

인앱 결제는 현재 없으므로 결제 금액/완료/취소/기기 변경 복원 항목은 미적용이다.
결제를 추가하면 해당 항목 전부 새로 검증해야 한다.
웹보드 항목은 동물 카드 게임이라는 이유만으로 자동 적용/면제라고 단정하지 않는다.
플랫폼의 게임 분류를 확인하고 적용 대상이면 성인 인증과 고객센터를 준비한다.
확률형 유료 아이템은 현재 없으며 일반적인 무작위 카드 섞기와 구분한다.
